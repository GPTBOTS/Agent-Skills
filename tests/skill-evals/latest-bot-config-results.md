# 最新 `.bot` 配置 Skill 评估结果

评估日期：2026-09-14

评估方式：三组独立只读评估最初比较 Skill `1.3.2` 与 `1.4.x`，功能分支 rebase 后已集成到当前 Skill `2.1.0`。评估按照 `latest-bot-config.md` 的行为标准检查文档路由、字段语义和校验器实跑结果。由于仓库没有配置 SkillHone 双模型执行器，本次属于定性行为评估，不是线上模型稳定性统计。

| 场景 | 旧版 | 新版 | 主要变化 |
|---|---:|---:|---|
| 服务提示 | 2/5 | 5/5 | 新增 `code=84`、组件级 `humanConfig` 和开关相反缺省值规则；校验器可拦截字符串开关与状态码 |
| 对话属性 | 1/5 | 5/5 | 区分 `.bot` 定义/默认值与会话运行时值；API 与 Variable 组件使用同一个已定义 key |
| 用户属性 | 1/5 | 5/5 | 新增七字段定义、类型/布尔值、命名冲突和用户运行时隐私边界 |

## 已确认缺口

- 旧版不知道 `humanConfig.multiLanguages` 的完整结构、`code=84` 或 `sendHumanTipSwitch` 的路径相关缺省语义。
- 旧版把 custom variable 描述为 Agent 全局变量，没有区分定义、默认值和会话值。
- 旧版没有 `userProperties[]` schema，也不会阻止 `accountId` 或嵌套用户值进入 `.bot`。
- 旧校验器会放过字符串形式的开关/状态码、非法属性定义和用户运行时数据。

## 新版验证结果

- 正确的顶层与 Flow Human 组件级配置通过。
- `sendHumanTipSwitch="true"`、`code="84"`、非法变量/属性类型、重复名称和跨数组名称冲突均失败并返回准确 JSON 路径。
- 未知整数服务状态 code 只告警，以兼容后端未来扩展。
- 非空的 `accountId` 和嵌套 `userProperties` 被判定为隐私错误；STG 官方导出的 `null` 占位键可通过，以保证导出文件可直接校验和再次导入。
- 平台合法导出的 `creativityLevel=1.0` 可通过，超过 `1.0` 仍按范围错误阻断。
- 对 `chatUpdate=false` 的属性，Skill 要求模型不得把调用尝试或 HTTP 成功误报为“已保存”，必须检查成功/失败列表，必要时回读确认。
- 旧 `.bot` 完全不包含这些新字段时仍可通过。
- Skill 明确要求用 Python 3.11+ 运行校验器；本机验证使用 Python 3.12。

## STG 导入导出回环

以下为历史验收记录；2026-09-18续测及修复结果见本文末尾。补测手写请求曾误用 `Locale: en-US` 导致 HTTP 500，不能据此认定导入文件或平台导入功能异常。

- 在 `https://stg.gptbots.ai` 成功导入 `latest-bot-config-valid.bot`，生成 Agent `Latest bot config fixture`。
- 再次导出的 `.bot` 保留了 `humanConfig.sendHumanTipSwitch=true`、`humanConfig.multiLanguages.en` 的 `code=36/84` 提示语、`customVariables[]` 和 `userProperties[]` 七个定义字段。
- STG 会为自定义变量和用户属性补充 ID、Bot/Project ID、时间等后端管理字段，并在用户属性中输出 `accountId: null`、`userProperties: null` 等空占位；校验器按官方导出行为兼容空占位，但继续阻断非空用户运行时数据。
- 将 STG 导出的文件再次从产品页面导入成功；验收结束后两个测试 Agent 均已删除。

## 评审反馈复核

- 使用 `creativityLevel=1.0` 的 `.bot` 在 STG 产品页面导入成功；校验器已改为接受平台合法闭区间 `[0,1]`，并新增 `1.0` 通过、`1.01` 失败的边界测试。
- 后端运行时仅在属性出现在成功列表时真正落库；`chatUpdate=false` 会把 LLM 更新放入失败列表，但外层 HTTP/工具响应仍可能成功。该规则最初在 Skill `1.4.1` 引入，现已集成到 `2.1.0`，要求模型检查成功/失败列表，强一致场景回读，禁止仅凭调用成功回复“已保存”。
- STG 模型回复复现未形成有效结论：测试 Agent 被环境自动分配到已下线模型，聊天返回 `Model does not exist`，没有产生属性更新工具调用。该测试 Agent 已删除；第二项结论来自后端执行链路核查，不冒充模型实测结果。

用户属性的七个生成字段由 Skill 规范和有效 fixture 保证。校验器强制 `name`、`type`、布尔字段类型、名称唯一性及隐私边界，但不强制旧导出文件补齐非关键展示字段，避免破坏兼容性。

## 2026-09-18 续测与修复

- STG页面已验证默认值引用、属性读写权限、真实成功/失败集合识别及回读、用户属性跨会话保持、Flow变量即时赋值/跨轮保持/会话隔离、定义默认值不被运行值覆盖，以及Human开关的true/false/null/缺失配置往返。
- 公开API已验证变量注入、后续轮次保持、独立会话隔离、未知变量不落定义、错误格式拒绝和空对象边界；未以HTTP 200直接判定业务成功。
- 已修复Flow Human缺配置告警、两处文档冲突和STG Variable成功出口误拒绝。LoopAgent更新指南要求保留已有导出的完整clawRule；变量指南区分builder输入与平台导出格式。
- 新增30个双入口回归用例；修复前目标缺陷造成6失败、24通过，修复后全部通过。全仓95项测试通过，Skill严格校验0错误/0告警。
- 5份未改写的STG Flow原始导出通过脚本及模块入口，输出一致。仓库回归夹具移除了环境和账号标识，仅保留重现所需定义、节点与连线。
- LiveDesk code84、LiveChat code36仍缺真实测试渠道，未完成运行时开关对照；不能宣称完整端到端验收全部通过。原始日志和环境测试资源留在本地，未作为仓库发布内容。
